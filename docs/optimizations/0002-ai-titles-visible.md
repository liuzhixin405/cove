# 0002 让 AI 标题看得见：补齐已有会话、即时应用、显示在窗口标题

- 状态：已完成
- 日期：2026-11-18（创建）；2026-11-18（完成）
- 关联：[0001](0001-unified-session-history.md)（AI 标题在 0001 里实现；本文处理它"看不见"的问题）

## 背景

用户安装 0001 的版本后反馈："测试发现 cove 没有使用 AI 标题的功能"。

## 现状与问题

证据（`~/.cove/sessions`，2026-11-18）：新版本在 18:27 编译并替换了 `D:\cove.exe`；之后新建的会话 `79eddd8a`，在第一轮完成后得到了 AI 标题"ILoggerProvider 简单控制台示例"（`title_source: ai`），而它的第一条输入是"给我一个简单的iloggerprovider的例子，不需要写文件"。**生成本身是正常的。**18:27 之前的会话，全部仍然是从第一句话截取的标题。

**P1 已有的会话永远拿不到 AI 标题。** 标题只在新版本里"有任务完成"时生成（`Titler::task_end`）。用户打开 `/resume` 列表，看到的几乎都是旧会话，所以感觉功能没有生效。

**P2 当前会话的标题会晚一步。** `Application::apply_titles` 在读取下一条输入之前运行（`app/mod.rs` 的 `repl_lines` 循环开头），而生成标题需要几秒钟。所以标题要等用户再提交一条输入、下一轮循环时才会写进会话；在这之前打开的列表看不到新标题。

**P3 当前会话的标题在界面上没有显示的地方。** `/resume` 不列出当前会话；`/continue` 只在当前任务未完成时列出它；状态行也不显示标题。Claude Code 会把标题显示在终端窗口的标题栏上。

## 目标

1. 打开历史面板时，列表里还没有 AI 标题的会话会在后台逐个补上标题，补好一个，面板里就刷新一个。
2. 当前会话的标题一生成，就在下一次处理输入之前写进会话，不再晚一步。
3. 当前会话的标题显示在终端窗口的标题栏上：`cove · <标题>`。

## 范围

- 做：上面三条。
- 不做：
  - 一次性给所有历史会话补标题：只补列表里实际显示的会话，用户看不到的不花这个钱。
  - 修改生成时机（第 1、2、3 轮之后各一次，之后每 5 轮）：这个规则 0001 已经定好。

## 方案

- **补标题**：`Titler::backfill(store, sessions)`。历史面板打开时（只在交互控制台里），把列表中 `title_source == Prompt`、有对话、而且本进程还没处理过的会话交给它，每次最多 20 个，按从新到旧的顺序。在**一个**后台任务里依次生成，不同时发出多个请求。生成好一个，就**加锁后直接写回存储**（这些会话不是当前会话，内存里没有副本，不会出现覆盖的问题）；拿不到锁（比如被另一个 cove 进程占用）就跳过。写回之前重新读取一次会话，如果期间用户改过名（`title_source == User`），就不覆盖。
- **刷新面板**：`Titler` 增加一个通知回调 `(会话 id, 标题, 是否当前会话)`，由 `Services` 设置成调用 `Console::retitle`。它会更新打开着的面板里对应那一行的标题并重画；如果是当前会话，同时设置窗口标题。
- **即时应用**：在读取到一行输入、开始处理之前，也调用一次 `apply_titles`。
- **窗口标题**：`Console::set_window_title` 输出 OSC 0（`\x1b]0;…\x07`）。启动或恢复会话时，用当前会话的标题设置一次；AI 标题或 `/rename` 改了标题之后，再设置一次。

## 影响范围

- `src/session/titles.rs`（backfill、通知回调）、`src/commands/sessions.rs`（打开面板时触发补标题；`/rename` 后设置窗口标题；创建 Titler 时设置回调）、`src/app/console.rs`（`retitle`、`set_window_title`）、`src/app/history.rs`（按 id 改标题）、`src/app/mod.rs`（读到输入后再应用一次标题；启动和恢复时设置窗口标题）。
- 费用：打开列表时，没有 AI 标题的会话每个多一次短的模型调用（用户确认不考虑费用）。

## 验证

- 单元测试：`HistoryView` 按 id 改标题；backfill 的筛选条件（跳过 User 和 Ai 标题、跳过空会话、最多 20 个、跳过已处理过的）。
- 全量 `cargo test` 通过。
- 人工确认：打开 `/resume`，旧会话的标题在几秒内逐个变成 AI 标题；新会话完成第一轮后，窗口标题栏变成 `cove · <标题>`。

## 决策记录

- 2026-11-18：只给面板里实际显示的会话补标题，每次打开最多 20 个，依次生成。理由：用户看不到的会话不花钱；依次生成可以避免同时发出大量请求。（实施方）

## 验证结果

- 新增单元测试：`backfill_takes_prompt_titled_conversations_once`（只选取标题来自第一句话、并且有对话的会话；同一个会话只排队一次；每次最多 20 个；关闭时不选取），`a_new_title_replaces_the_listed_one`（面板按 id 更新标题）。
- `cargo test` 全部通过：单元测试 407 个，集成测试 224 个。只对改动过的文件，通过标准输入运行了 rustfmt。
- `cargo build --release` 已完成（`target/release/cove.exe`）。
- 人工确认（2026-11-18，用户："现在好了"）：打开 `/resume`，旧会话的标题在几秒内逐个变成 AI 标题；新会话完成第一轮后，窗口标题栏显示 `cove · <标题>`。

## 遗留

- 补标题只在交互控制台打开面板时触发，文本列表（`-p`、管道、`--list-sessions`）不会触发。这是有意的：非交互场景里看不到逐个刷新的效果。
- Windows Terminal 允许用户在设置里禁止程序修改标签页标题；如果关闭了这个权限，窗口标题不会变，这是终端自身的设置。
