# 0009 回滚点按任务记录，存储按时间清理

- 状态：已完成
- 日期：2026-11-20（创建）；2026-11-20（完成）
- 关联：同类功能统一分析（第五组）

## 背景

同类功能统一分析的第五组：回滚和存储清理。原来列出的问题是"Git 快照占 168MB、`/undo` 有两套、没有保留策略"。

## 现状与问题

**两套回滚机制，用同一个 `/undo` 展示。**

| | 文件工具检查点 | Git 快照 |
|---|---|---|
| 代码 | `session/workspace.rs` | `session/snapshot.rs` |
| 记录什么 | write/edit 改动前的原文，按任务记录 | 整个工作区（包括 Shell 的影响），存在私有的 bare 仓库里 |
| 什么时候记 | 每次文件工具写入 | **每次** write、edit、会改东西的 shell、写入型子代理调用**之前** |
| 恢复 | `/undo confirm`：只回滚上一个任务 | `/undo #n`、`/undo files`：任意快照 |
| 保留 | 跟会话一起清理 | 每个项目 50 个，攒到 60 个才清理一次；没有时间限制 |
| 占用 | 9MB（431 个文件，没有孤儿文件） | 166MB |

文件工具检查点不只用于 `/undo`。编辑时核对文件有没有被改过、确认状态不明的工具调用、`/diff`、`/changes apply` 都靠它，所以不能删。

**P1 快照库 166MB，其中约 150MB 是一个早就被排除的代码索引数据库。**
- 最大的几个对象都是 QuoteHub 的 `.codeatlas/index.db` 和 `index.db-wal`：原始大小 259MB 和 213MB，压缩后共约 150MB。
- 这些是 11-13 拍进去的，当时还没有排除 `.codeatlas/` 的规则。规则加上后，11-18 起的新快照里已经没有它们了。
- 旧快照还在，是因为清理要攒到 60 个才触发，这个项目现在只有 51 个。即使触发，也要等这些快照排到最新 50 个之外才会删。按现在的速度，还要好几周。
- 其他 5 个项目合计不到 1MB。

**P2 每次改动前都拍一次快照，单次约 0.3 秒。**
- 在 QuoteHub 上实测（存储放在临时目录）：首次快照 9.0 秒，之后工作区没有变化时每次约 0.28 秒。
- 历史记录里，edit 672 次、write 54 次、shell 1194 次（其中会改东西的要拍快照）。连续编辑同一个任务里的几个文件，每次编辑前都要等一次。
- 这种粒度是"每次调用"。Claude Code 是每发一次提示建一个检查点（每个会话保留最近 100 个，默认约 30 天后随会话清理），只跟踪文件工具的编辑，不跟踪 Shell。
- 你的 572 条输入历史里，`/undo` 和 `/diff` 一次都没用过。

**P3 `/undo` 一次列出两种东西**："文件工具回滚（只回滚上一个任务的 write/edit）"和"Git 快照列表（标签是'before edit: 某文件'）"。要先弄明白这两者的区别才能选，而快照的标签只说"改哪个文件之前"，看不出是哪个任务。

**P4 小问题：剪贴板图片从不清理。** `clipboard/` 下有 27 个文件、4MB，从 10-28 起一直累积。图片发送时已经以 base64 写进会话，会话里没有引用这些文件，发出之后就用不到了。

## 目标

1. 回滚点按任务记录，`/undo` 只列一种东西：每个任务开始前的状态，标签是那次请求。
2. 编辑文件时不再每次都等一次快照。
3. 快照按数量和时间清理，过期的大对象能及时删掉。
4. 清理一次 QuoteHub 的旧快照，释放约 150MB。

## 范围

- 做：
  - 快照的时机；
  - `/undo` 的展示和命令；
  - 快照的保留规则；
  - 剪贴板图片的清理；
  - 一次性清理 QuoteHub 的旧快照。
- 不做：
  - 不删除文件工具检查点：它是编辑核对和状态不明调用的基础；
  - 不改快照的排除规则（`.gitignore`、2MB、构建目录等）：它们已经能挡住这类文件，P1 是规则出现之前留下的；
  - 两份"会不会改东西"的判断（`snapshot.rs` 和 `safety/gates/plan.rs`）回答的问题不同：一个问"会不会改工作区文件"，一个问"会不会改任何状态"。本次不合并，只在遗留里记一笔。

## 方案

**1. 快照时机：每个任务一个，Shell 和子代理前另拍。**
- 一个任务里第一次要改东西之前拍一个快照，标签是本次请求（例如"任务：修复登录 bug"）；
- 之后同一任务里的 write、edit 不再拍：它们之间的回退由文件工具检查点负责；
- 会改东西的 shell 和写入型子代理之前仍然拍：它们的影响只有快照能覆盖。标签是"任务内：npm install"这样的说明。

**2. `/undo` 只列一种东西。**

```
/undo            列出最近 10 个回滚点（按任务分组，最新在前）
  #1 11-20 14:02  任务：修复登录 bug
  #2 11-20 13:40  任务内：npm install（任务：修复登录 bug）
  #3 11-20 11:15  任务：加上分页
/undo #n         预览恢复到这个点：列出会变动的文件
/undo confirm    执行最近一次预览（恢复前的状态先拍一个快照，可以再撤销）
/undo files #n <文件…>  只恢复指定的文件
```

- 快照不可用时（没有 Git、工作区是主目录或根目录、快照太慢被关掉），`/undo` 退回"文件工具回滚：上一个任务的 write/edit"，并说明原因。
- 去掉单独的 `/undo confirm` 和 `/undo list`：它们是"两套机制"的入口。

**3. 保留：每个项目最多 50 个，最长 30 天。**
- 每次拍快照后检查：超过 50 个，或者最旧的超过 30 天，就清理；不再等攒到 60 个。
- 清理后照旧在后台做 `git gc`。

**4. 剪贴板图片保留 7 天**，启动时清理更早的。

**5. 一次性清理 QuoteHub 的旧快照**：删掉 11-18（排除规则生效）之前的快照，然后做一次 `gc`。

## 影响范围

- 文件：`src/session/snapshot.rs`、`src/commands/sessions.rs`（`/undo`）、`src/commands/project.rs`（帮助）、`src/app/paste.rs` 或启动流程（剪贴板清理）、`docs/reference.md`。
- 行为变化：
  - 同一任务里的连续编辑不再各自拍快照，回滚点的粒度从"每次调用"变成"每个任务，以及每次会改东西的 Shell"；
  - `/undo list` 和 `/undo confirm <确认码>` 不再存在，统一为 `/undo`、`/undo #n`、`/undo confirm`；
  - 30 天以前的快照和 7 天以前的剪贴板图片会被删除。

## 验证结果

- **存储**：
  - QuoteHub 的快照从 51 个减到 2 个（只留 11-18 01:05 以后、已经没有 `.codeatlas` 的）；
  - ccs-backend（14 个，最新 11-02）和 vfx-price-engine-mono（5 个，最新 11-17）的快照整个删除；
  - 仍在引用的数据只剩 1.9MB；
  - 不再引用的 155MB 现在在 cruft pack 里。因为当时有一个 cove 进程在运行，没有用 `--prune=now` 强制回收，免得删掉它正在写的对象。满 1 小时后，下一次打开快照库时会在后台删掉。
- **新增测试**：
  - 同一任务里两次 edit 加一次 `draw_image` 只产生一个快照（"任务：…"），会改东西的 Shell 另有一个（"任务内 shell: …"），read 不产生快照，下一个任务产生新的快照；
  - 超过时间的快照被清理，至少保留最新一个；在数量和时间限制以内不变；
  - 最新快照超过 30 天的其他项目被整个删除，连同它的 index，自己的项目不删；
  - 只有超过 1 小时的 cruft pack 才算可回收；
  - 剪贴板只删 7 天前的 `clipboard-*.png`，不碰其他文件。
- **改写的测试**：`/undo` 的三个集成测试改用新命令（`/undo` 列出、`/undo #n` 预览、`/undo confirm` 执行），断言新的标签"任务：run the script"。
- `cargo test` 全部通过：单元测试 385 个（另有 4 个忽略），集成测试 215 个。
- 只对改动过的文件，通过标准输入运行了 rustfmt；`cargo build --release` 完成。
