## 现状与问题

**P1 有两处写错。**
- 写着用 `/usage` 查看花费，实际命令是 `/status usage`。用户自己的输入历史里就打过 3 次 `/usage`，都报了"未知命令"；
- 写着"点击用户消息开头的三角，用鼠标滚轮浏览对话"，代码里没有这个功能。0001 做的是 `/turns` 历史阅读器。

**P2 只罗列操作，没讲清楚 cove 有什么不同。** 开头三条（一个 exe、全中文、会话自动保存）是所有同类工具都会写的。真正有分量的能力几乎没提，这些都是 0001–0013 做出来的：
- `/undo` 能撤销 Shell 命令造成的改动；
- 费用按实际作答的模型、区分缓存读写计算；
- 长会话不会越用越慢；
- 一个需求两个方案（`/race`）；
- 历史面板和阅读器。

**P3 夹着更新日志式的句子。** 比如"不再自动生成技能"，读者看不懂，也不需要知道。

**P4 安装只写了"把 cove.exe 放到某个目录"**，没写从源码构建。

## 目标

README 让第一次打开仓库的人在一分钟内知道：
- 这是什么；
- 和同类工具相比强在哪；
- 怎么装、怎么开始；

细节都指向 `reference.md`。所有写进去的命令和功能都要在代码里核实过。

## 方案

结构：
1. 一句话定位，加 5 条有实质内容的亮点；
2. 快速开始：安装、从源码构建、第一次运行、示例；
3. 日常操作（表格，已核实）；
4. 权限与模式；
5. 会话、历史与撤销；
6. 进阶：子任务和后台 Agent、`/race`、MCP、技能、记忆、非交互运行；
7. 配置；
8. 安全须知；
9. 文档索引（含 `docs/optimizations/`）。
