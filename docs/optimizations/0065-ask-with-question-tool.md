# 0065 需要用户回答时用 question 工具提问，不再以结束一轮来提问

- 状态：已完成
- 日期：2026-11-28（创建）；2026-11-28（完成）
- 关联：0044（系统提示每条规则只写工具说明里没有的内容）；0062（测试统一用 debug 构建，收尾验证复用结果）

## 背景

用户让模型"修复插件报错再推送"。模型缺信息（要改什么、推送用哪种凭据），在回复正文里写"请告诉我……"，然后结束这一轮。用户在这一轮收尾时输入回答，界面提示"任务已先结束，这条内容作为新消息发送"，回答成了一条新消息。连续三次都是这样：每次需要用户选择，都以结束一轮告终，而不是等回答后接着做。

现象出现在 0.8.1。2026-11-28 在 0.8.2（`cove 0.8.2+52ce76a`）上复现：模型在回复末尾写"如果你确认要推，我可以……"后结束这一轮，没有调用 `question` 工具。

## 现状与问题

- 系统提示（改动前 `src/engine/agent.rs:2870-2889`）只有一条"缺少外部条件就说明并结束"（`agent.rs:2873`），会把模型推向"问完就结束"。没有任何一条要求"需要用户回答时调用 `question` 工具"。
- `question` 工具会阻塞等待回答，回答后任务继续（`src/tools/mod.rs:1046` 取用户输入，定义在 `mod.rs:1513-1526`）。但工具说明没写它和"在正文里提问"的区别。
- 用户在一轮收尾时（例如收尾验证还在跑）输入的回答，会被当成新消息送入，并带上 `[sent while the previous task was running]` 前缀（`src/app/mod.rs:564-567`）。这一轮的计划和中间结论就断了。

## 目标

- 有 `question` 工具时，遇到需要用户回答、选择或补充信息才能继续的情况，模型调用该工具，回答后接着做这一轮。

## 范围

- 做：系统提示加一条规则；`question` 工具说明补一句。
- 不做：
  - 改 steer 的送入机制。用户在任务进行中主动插话、作为新消息送入，是预期行为。问题在于模型不该用结束一轮的方式提问。
  - 收尾检查（回复以问句结尾时提醒改用工具）。要靠"是不是问句"来判断，可能误判。先看 A1 的效果。
  - 收尾验证的测试范围，见"遗留"。

## 方案

1. **A1（采用）**：系统提示在"说明并结束"那条（`agent.rs:2873`）后面加一条：有 `question` 工具时，需要用户能给出的回答、选择或信息才能继续，就调用它，不要在回复末尾提问后结束；只有需要用户在 cove 之外动手时（启动服务、授权），才说明并结束。后半句划清它和 2873 那条的边界，否则"缺凭据"这类情况两条都能套上。
2. `question` 工具说明加一句机制："The task waits for the answer and continues."
3. **A2（不采用）**：在 A1 基础上加收尾检查，回复以问句结尾时提醒模型改用工具。

## 决策记录

- 选 A1，不选 A2：用户决定，先观察效果。
- 系统提示和工具说明各写一半，不逐字重复（0044 原则）：系统提示写"什么时候用"，用来抵消 2873"说明并结束"带来的倾向，这只有系统提示能做；工具说明只写机制。

## 验证

- 没有测试断言系统提示或工具说明的原文。`cargo test system_prompt`：通过（4 passed，包括 `--dump-system-prompt` 和系统提示相关的集成测试）。
- 实际交互：需要选择时界面出现 `[Q1/N]`，回答后同一轮继续。这一项依赖模型行为，只能抽样观察。本次方案选择就是用 `question` 工具问的，回答后在同一轮里接着改。
- 遗留一处未改：卡住提示 `agent.rs:448` 也写着"say so and finish"，影响小，先不动。

## 遗留

- **收尾验证在 cove 上总是跑全量 `cargo test`（暂缓，不改代码）。**
  - 现状：纯问答不触发收尾验证。只有本轮用文件工具改了非文档、非忽略的文件才会跑（`src/safety/verify.rs:1456-1464`），每个任务开始时新建检查点（`src/app/mod.rs:1279`）。
  - 但根目录 `Cargo.toml` 没有 `[workspace]`，`whole = !workspace` 恒为真，改一个 `.rs` 文件就跑全量 `cargo test`（`verify.rs:172`、`196-197`）。本机账本最近 5 次每次 149-158 秒。
  - AGENTS.md 三.5 还要求模型收尾时跑全量，改两个字符串也会照做。
  - 候选方案：
    - B1：改 AGENTS.md 的测试规则，只在提交前、改公共模块或 `Cargo.toml`/`tests/` 时跑全量；不改代码。
    - B2：单 crate 时按改动文件推出模块过滤器，生成 `cargo test --lib <模块>`。
  - 决定前先计时：编译和运行各占多少。如果大部分是编译，B2 收益有限。
  - 用户决定：后面使用中再看有没有必要。
