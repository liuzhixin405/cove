# cove 架构设计

版本：0.3.2。本文说明 cove 的目标、模块划分、设计原则和关键机制；使用方式、命令和实际限制见 [使用说明](../README.md)、[技术参考](reference.md)，扩展配置见 [扩展使用说明](extensions.md)。

## 1. 目标与非目标

cove 是一个以编码任务为中心的终端 Agent：读代码、改代码、运行命令、验证结果，并且在中断、崩溃和用户并发修改面前保持可恢复、不越权、不伪造结论。

目标：

- 用强类型表达消息、工具调用、审批与任务状态，减少隐式状态串接。
- 单一执行内核：交互控制台、`-p` 单次任务、子 Agent 和后台 Agent 走同一条执行路径。
- 安全默认值：集中权限判定、项目信任、路径与进程边界，所有可写扩展受同一套规则约束。
- 可恢复：执行意图先于副作用落盘，结果先持久化再展示，结果不确定的调用不自动重放。
- 有界：模型调用次数、输出、上下文、预算、时间、并发和输出缓冲都有上限，超限明确报告。
- 少入口：用户命令集中在 `/help`、`/model`、`/config`、`/status`、`/resume` 等少数入口下，子功能作为子命令。

非目标：

- 不承诺换用 Rust 就让模型更会编码；效果主要取决于上下文、工具、提示和验证。
- 不做全屏 TUI、通用工作流引擎、DI 容器、事件总线或通用插件框架。
- 不引入大型 Agent 框架：消息、工具、策略与循环正是产品需要自己掌控的部分。
- 不加载原生动态库插件；插件只提供提示文本、技能数据和受控的扩展进程配置。
- 不把检查点或 worktree 当作沙箱：Shell 和扩展进程拥有宿主权限。

## 2. 用户交互

日常使用以自然语言任务为主：

```text
cove
cove -p "修复这个测试失败，并运行相关测试"
cove --resume <session-id>
```

- 模型看到的工具和用户看到的命令是两份不同的清单。
- 不认识的斜杠命令明确报错，不作为提示发送并产生费用。
- `-p` 不读取审批输入；缺少授权时明确失败，并保留恢复所需的信息。
- 交互控制台（`app/console.rs`）由一个线程独占键盘，输出绘制在输入行上方。任务运行时输入的普通文字通过 `SteerHook`（一个 `TurnHook`）在下一次模型调用时交给模型，斜杠命令排队；审批和提问通过同一输入行回答。控制台只实现 `UserInput` 等小接口，内核不知道它的存在。
- 补全的子命令从 `/help` 用法行解析（`app/completion.rs`），帮助文本是命令清单的唯一来源。`/mcp`、`/plugins`、`/hooks`、`/memory` 是 `/config` 子入口的简写，在分派落空时改写成 `/config …` 再分派一次（同名技能优先），不复制处理代码。
- 呈现分两种，由 `console::rich()` 决定，同一份 `Event` 流驱动：
  - **交互控制台**（`app/ui.rs` 的 `rich_events` 与 `app/render.rs`）：每种输出各成一块：用户输入在灰底色块里，模型回复以白色 `●` 开头并按 Markdown 渲染，隐藏的思考留一行 `✻ 思考了 Ns`，工具调用是青色 `●` 标题加 `└` 摘要。`Event::ToolStarted` 携带调用参数，标题（如“读取 src/main.rs”“运行 cargo test”）在渲染层生成。工具标题等到第一行实时输出或结果到达时才写，所以并行的只读调用不会留下一排空标题。状态行显示当前活动、耗时和 token。
  - **`-p`、管道和简单模式**：保持 `[tool]`、`[ok]`、`[summary]` 等机器可读行，竞跑 worker 和测试解析它们。
- Markdown 渲染是一个流式状态机（`render::Markdown`）。它只在一行的开头标记或单个 `*` 还不能判断时暂缓输出，其余文字立即显示。控制台每次写出后都会重置样式，所以下一段输出开头会重新打开仍在生效的样式（代码、粗体、标题）。表格先收齐所有行，再按显示宽度对齐。
- 审批提示的结构由权限模块给出：首行“需要批准”，接着是操作描述和警告，最后一行是 `是否允许？[y/N/a=…]`。黄色边框由 UI 层加上，按键解析不受影响。

## 3. 工程结构

一个 Cargo package（`cove`，Edition 2024），按职责分目录，每个目录的 `mod.rs` 开头说明它负责什么：

```text
cove\
  Cargo.toml
  assets\        编译进二进制的内置技能
  marketplace\   内置技能市场：registry.json 与 skills/<名字>/SKILL.md，编译进二进制
  src\
    main.rs       进程入口：参数、-p 管道输入、双击启动、退出码
    lib.rs        模块声明
    domain.rs     跨模块共享的核心类型（消息、事件、Provider/UserInput 接口、错误）
    process.rs    子进程与进程树管理（Job Object / 进程组）
    process\      argv 拼装、Shell 选择与方言、门控 stdio 宿主
    app\          组装根与终端：Application、启动/重启、设置向导、交互控制台（输入行、补全、历史、插话/排队/中断、行内问答、选择器、Agent 面板、图片粘贴）、诊断、/init
    config\       配置加载与合并（用户配置、profile、.cove.json）、项目信任
    engine\       执行内核：Agent 循环、上下文估算与压缩、TurnHook、系统提示、子目录指令提示、工具输出管理
    model\        模型访问：两类协议与 Bedrock Runtime、事件流解析、模型路由、模型表、图片、网络代理
    tools\        模型可调用的工具：文件/搜索/Shell/提问/todo、repo_map、网页、画图、浏览器，以及扩展工具组合
    agents\       子 Agent：委派、后台 Agent 与生命周期、execute_plan、worktree、回归验证、实验性协作工具
    safety\       权限模式与规则（permission/）、Shell 分类与危险命令、完成闸门（gates/）、验证门禁
    session\      会话存储（sessions/ 完整快照 + journals/ 追加日志，History 区分追加与改写）、文件检查点、Git 快照、费用账本、会话笔记
    memory\       长期记忆：存储、检索注入、自动提取、dream 整理
    extensions\   技能、插件、Hooks、MCP（stdio 与 HTTP/SSE）及启停注册表
    workflows\    外围工作流：竞跑、自动化任务与收件箱、变更集、远程监督、浏览器验收
    commands\     斜杠命令，按功能区分文件，每个文件提供 HELP 与 handle
  tests\          集成测试，按功能区命名（cli、core、persistence、sessions、safety、tools、model、agents、extensions、integrations、project、workflows）
```

只有一个 package；有独立复用、编译隔离或测试收益时才拆 crate。

依赖方向自上而下：`app`/`commands` 组装并调用其余模块；`engine` 只依赖 `domain`、`model` 的接口和 `TurnHook` 等扩展点；`tools`、`safety`、`session`、`extensions` 等不反向依赖 `app`。

```text
交互控制台 / -p
   ↓ 任务请求、审批回答
App（组装根）→ Agent 执行内核
   ├─ Provider：模型协议与流式解析（含路由、计量装饰器）
   ├─ ToolExecutor：参数校验、权限、调度和结果
   ├─ SessionPersistence / Context：持久化与上下文
   └─ TurnHook / Lifecycle：闸门、记忆、技能提示、Hooks、插话
             ↓
       文件 / 进程 / Git / 网络 / 浏览器等具体能力

内核与工具 ──有界事件通道（Event）──→ 终端
```

内核依赖的小接口（`domain.rs`、`engine/turn.rs`、`session/mod.rs`、`tools/mod.rs`、`extensions/hooks.rs`、`safety/`）：

| 接口 | 职责 |
| --- | --- |
| `Provider` | 发出一次流式模型请求，通过有界 channel 推送 `Event` |
| `UserInput` | 向用户提问并等待回答（审批、`question` 工具） |
| `ToolExecutor` | 工具定义、是否可并发、执行 |
| `SessionPersistence` | 保存会话、归档压缩前的上下文 |
| `TurnHook` | 任务首条消息附注、工具前拒绝、工具结果附注、收尾催促、任务结束；所有方法有空默认实现 |
| `Lifecycle` | 会话/任务/工具生命周期上的 Hooks |
| `Authorizer`、`Verifier`、`ProjectTrust`、`ModelPolicy` | 权限判定、完成前验证、项目信任查询、模型选择策略 |

约束：

- 内核不打印终端；工具不直接读键盘；Provider 不知道 UI。
- 每个 Agent 的对话状态由一个任务拥有，不全局共享可变消息列表，也没有覆盖整个应用的大锁。
- HTTP client、不可变配置和必要的服务句柄可以共享；不为避免生命周期问题而到处克隆整个会话。
- 工具注册、策略检查和执行路径只有一套；扩展工具通过组合 `ToolExecutor`（`tools/extension_tools.rs`）进入同一调用日志，不另绕捷径。

## 4. 设计原则

架构遵循高内聚、低耦合、单一职责、依赖倒置、接口隔离和组合优于继承，同时遵守 KISS、YAGNI 与 DRY。以减少认知负担和变更影响面为判断标准，不以层数、trait 数量或设计模式数量衡量质量。

| 原则 | 在本项目中的落地 |
| --- | --- |
| 单一职责 | Agent 编排执行流程；Provider 处理模型协议；权限模块做决策；进程模块管理启动/输出/清理；控制台负责交互和渲染 |
| 依赖倒置 | 内核依赖自身需要的小接口和领域类型，不依赖具体 HTTP、终端、MCP SDK 或浏览器类型 |
| 接口隔离 | 不建立覆盖模型、文件、Git、浏览器和记忆的万能 Runtime/Service trait；每个接口只服务清晰调用方 |
| 开闭原则 | 新增供应商和工具通过适配与注册接入，不在主循环追加供应商名、工具名判断 |
| 行为可替换 | 不同适配器遵守相同取消、错误和结果契约；不支持的能力显式声明，不返回伪成功 |
| 组合优于继承 | 工具能力、授权和资源限制通过组合实现；不模拟面向对象继承体系 |
| KISS / YAGNI | 先具体实现真实需求；不预建通用工作流引擎、DI 容器、事件总线或插件框架 |
| DRY | 统一权限、取消、预算、进程和协议处理等业务规则；不因几行代码相似就强行抽象不同业务 |

### 4.1 模块边界与组装

- 领域类型（任务、消息、工具调用、结束原因）不包含终端控件、HTTP 响应或 SDK 对象；协议专有字段在边界封装。
- `app` 是组装根：读取配置、构造具体实现、注入依赖并管理应用生命周期，不承接模型循环和工具业务。
- 终端发送显式请求、消费事件，不读取或修改内核私有字段；内核也不反向查找 UI 或全局服务。
- 文件、进程、Git、网络与浏览器能力在明确边界执行；扩展不得绕过授权调度去操作宿主环境。
- 小接口通过构造函数和普通结构体组装，不使用全局 service locator；trait 只用于真实替换边界。
- 单向依赖体现在模块可见性与公开 API 上；避免大面积 `pub`、跨模块访问内部状态和循环依赖。

### 4.2 采用的模式

| 模式 / 思路 | 使用位置 | 限制 |
| --- | --- | --- |
| Adapter | Provider、MCP、浏览器（精简 CDP 客户端）、会话存储 | 将外部协议转为稳定内部类型；不为每个函数再包一层转发 |
| Strategy | 权限决策、模型路由、上下文压缩 | 确有多种可替换规则时才抽取 |
| 显式状态机 | 回合状态、审批等待、工具生命周期、后台 Agent 状态 | 用 enum 和受控转换表达合法状态，不用多个布尔值拼出隐含状态 |
| Command + Registry | 工具请求与斜杠命令分派 | 注册表只负责发现与查找，不变成万能管理器 |
| Decorator | 模型请求计量（费用账本）、诊断轨迹 | 只在真实调用边界附加；不重复重试、重复计费或吞掉原始错误 |
| 单一状态所有者与消息传递 | Agent、后台任务、交互事件 | 有界 channel 和明确请求/应答，不引入 Actor 框架 |
| 显式生命周期管理 | 子任务、进程、worktree、浏览器 | 由创建方负责停止和回收；RAII 只作兜底，异步清理显式、有界、可观察 |

### 4.3 防止架构膨胀

- 不建立万能 `Engine`：模型传输、文件编辑、权限规则和 UI 渲染都不塞进执行循环。
- 不机械增加 Controller → Service → Manager → Repository 等仅转发的层。
- 不用 `serde_json::Value`、字符串事件名、`Any` 或向下转型绕过核心类型约束；动态 JSON 只在协议边界出现。
- 不把所有异步调用都 `spawn`；只有需要独立生命周期或实际并发时才创建任务，并由拥有者收拢。
- 有界 channel 需要背压策略：文本增量可批量发送，状态和工具结果不能静默丢弃。
- 会话日志用于恢复和诊断，不升级成 Event Sourcing/CQRS 平台，不支持任意重放有副作用的操作。
- 重试由单一明确层拥有，并区分传输失败、限流、协议错误和结果不确定。
- 权限与限额在有副作用的执行边界强制检查，不依赖调用者“记得检查”。
- 新增抽象必须说明它隔离了什么变化、维护什么不变量，或消除了什么真实重复。

### 4.4 架构验收

1. 用 fake Provider、工具执行器和存储即可测试内核，无需真实网络、终端或浏览器。
2. 新增一个模型适配器不修改主循环；新增普通工具不修改 UI 和权限执行管线。
3. 交互与 `-p` 复用同一执行语义，不各自实现审批、取消、会话保存和重试规则。
4. 所有可写扩展与子 Agent 受同一授权和资源限制，不能通过替换实现突破不变量。
5. 非法状态转换、通道关闭、取消、清理失败及结果不确定均有明确测试与错误输出。

## 5. 技术选型

实际依赖由 [Cargo.lock](../Cargo.lock) 锁定。

| 职责 | 选择 | 说明 |
| --- | --- | --- |
| 语言 | 稳定 Rust、Edition 2024 | CI 固定工具链版本，不依赖 nightly |
| 异步 | Tokio、tokio-util | 网络、进程 I/O、超时、`CancellationToken` 取消与任务收拢 |
| HTTP | reqwest（rustls、系统代理、SOCKS） | 模型请求、MCP HTTP/SSE、网页工具共用；网页工具额外做地址校验与 DNS 固定 |
| JSON / YAML | serde、serde_json、serde_yaml_ng | 内部强类型，协议扩展字段保留在明确边界 |
| CLI | clap | 参数校验、环境变量映射和帮助生成 |
| 错误 | thiserror；应用入口用 anyhow | 内核保留结构化错误，边界附加上下文 |
| 搜索 | ignore、globset、regex | 遵守 ignore 规则；有 ripgrep 时 `grep` 优先调用 `rg` |
| MCP | rmcp（stdio）+ 自带 HTTP/SSE 传输 | 使用官方 SDK 的客户端能力；HTTP 传输复用项目的 reqwest |
| 终端 | crossterm、unicode-width、unicode-segmentation | 常驻输入行和按字形簇编辑，不引入全屏 UI 框架 |
| Git | 调用 git CLI | 保持用户环境语义；argv 调用，不拼接不可信 Shell |
| 浏览器 | 自带精简 CDP 客户端（tokio-tungstenite） | 驱动已安装的 Chrome/Edge；每个请求经 Fetch 拦截做地址检查 |
| 远程监督 | hyper、tokio-rustls | 只监听 loopback 或带 TLS 的私网地址 |
| 平台 | windows-sys（Job Object 等）、arboard（剪贴板图片）、libc | 进程树回收与平台集成 |

## 6. 核心执行循环

```text
接收任务并记录
  → 收集项目指令、上下文、记忆附注与本次可用工具
  → 检查上下文、预算、时间和迭代上限（必要时自动压缩）
  → 选择模型（路由），调用 Provider，接收流式事件
  → 若有工具调用：
       等待参数完整并校验
       → TurnHook 前置检查（循环检测、计划模式等）
       → 权限判定，必要时等待用户审批
       → 记录执行意图并持久化
       → 执行（连续的只读调用并发，最多 8 个）
       → 持久化结果，附加工具结果附注
       → 送达用户插话，带工具结果继续请求
  → 若模型结束：
       收尾催促（空回复、todo 未完成、完成自检）
       → 改过文件时运行验证门禁，失败回给模型（最多 3 轮）
       → 完成 / 失败 / 取消 / 未验证
  → 写验收报告，保存会话快照，收拢本轮子任务
```

内部状态区分调用模型、执行工具、等待审批、等待用户回答、压缩、验证、停止。等待审批不是模型卡死，取消也不是成功。

### 6.1 消息与协议

- 用明确类型表达文本、图片/附件、工具调用、工具结果和 reasoning。
- opaque thinking blocks、签名和扩展字段原样保存与回传。
- 流式工具参数可能跨多个事件，完整校验前不执行；无效参数作为错误返回模型，不猜测执行。
- 工具结果关联正确 call ID；恢复、压缩和换模型都不破坏配对。
- 断流后不重复有副作用的工具，也不假设模型请求未计费。
- 两个协议适配器：OpenAI Chat Completions 兼容与 Anthropic Messages；Bedrock 走 Anthropic 协议加 Bedrock Runtime 事件流。

### 6.2 工具与调度

- 每个工具用专有输入类型反序列化；仅在协议边界使用动态 JSON。
- `shell` 区分 Git Bash/POSIX sh 与 PowerShell 方言，工具描述写明实际解释器。
- 连续的只读调用（read/glob/grep/repo_map、web_fetch/web_search）有界并发；修改类调用逐个执行。工具完成顺序可以不同，但写入历史的结果顺序与调用关联是确定的。
- `repo_map` 按文件修改时间和大小缓存解析结果，缓存未命中的文件在作用域线程上并行解析。
- 输出有字节/行数限制；旧工具输出外置到数据目录时有访问边界、生命周期和明确引用。
- MCP 只暴露一个 `mcp` 入口，按需连接，不在默认提示中塞入全部 schema。

## 7. 可靠性设计

### 7.1 会话存储与恢复

- `sessions/<id>.json` 始终是完整的会话快照（原子替换写入）；任务进行中的保存只向 `journals/<id>.log` 追加一条记录并同步到磁盘，避免每次重写整个文件。
- `History` 类型区分“追加”和“改写”：追加按原样记日志；压缩、掩码、替换历史开启新纪元，下一次保存写快照。任务结束、退出或日志超过 8 MiB 时也写新快照并清空日志。
- 读取时先读快照，再按序号重放快照未包含的日志记录；重放幂等，崩溃时写了一半的最后一条记录被忽略。
- 同一数据根中的同一工作区只允许一个写者（文件租约）。
- 执行意图存在、结果缺失的调用先按能确定的情况结算（`Application::settle_interrupted`）：
  - 没有副作用的调用（读取、搜索、提问、todo、网页读取）重新运行；
  - 写入/编辑先确认检查点记有意图，再看文件内容：是预期结果记为已完成，是原内容记为未执行（`Workspace::settle_edit`）；
  - 其余调用仍是“结果不确定”，不自动重放。
- 用户在未完成任务上发新消息时，旧批次被关闭（`close_unfinished`）：没运行的调用记为未执行，结果不明的如实记为不确定，什么都不重放，对话继续，而不是拒绝新消息。`/resolve` 仍可用于逐个确认。
- 估算 token 与费用标记为估算；未知价格不按零处理。每次请求前先落盘“费用未知”，收到 usage 后再更新。

### 7.2 文件与回退

- 支持中文路径、CRLF、BOM、GBK/GB18030、长行和大文件，编码错误明确报告。
- 编辑必须唯一匹配；空白容错匹配也只接受唯一结果。覆盖文件前必须读过当前版本。
- 修改前保存受影响文件的原件与哈希；回退前检查文件是否漂移，用户后续改动冲突时停止。
- 文件工具检查点不覆盖 Shell 副作用；整树 Git 快照（私有仓库，不碰项目 `.git`）覆盖工作区内的 Shell 改动，还原本身可再撤销。
- 没有 Git 仓库也能完成编码任务；Git 专用能力明确提示不可用。

### 7.3 多 worktree 与结果集成

- 可编辑的后台 Agent 各自使用从 HEAD 创建的独立 worktree 和分支；数量受并发上限约束。
- 父 Agent 自己的工具不切换根目录：检查点、验证门禁、`/undo` 和项目上下文都绑定主工作区。在 worktree 里工作通过根目录在该 worktree 的子 Agent 完成。
- 合并只在用户明确要求时执行，要求主工作区干净；冲突报告并中止，不静默解决。集成后旧验证证据失效。
- 任务完成、取消或进程退出不删除 worktree；未提交和未集成的成果保留，记录可恢复状态。
- worktree 共享 Git 管理数据和宿主权限，不是文件系统、进程或网络沙箱。

### 7.4 进程与取消

- 根任务持有 `CancellationToken`，子 Agent、请求和工具继承子 token。
- 取消时停止调度新工作、终止所属进程树、排空输出、有界等待并保存状态。
- Windows 用 Job Object，进程加入 Job 之后才通过 stdin 收到脚本；Unix 用进程组。不按进程名批量结束进程。
- 退出等待有上限，超时与清理失败可见。
- `-p` 读取管道 stdin 时，若既不是普通文件、stderr 也不是终端，只等首字节 3 秒，避免被从不写入的继承管道挂住。

### 7.5 权限、扩展与信任

- 权限集中评估读、写、进程、网络和越界访问；四种模式 `default`、`plan`、`auto`、`bypass`，灾难命令在任何模式下都拦截。
- “无法询问”和“用户说不”是两种错误：
  - `Error::Approval` 表示需要批准却无法询问，或被规则禁止。任务停下，调用回到计划状态，换权限后可 `/continue`。
  - `Error::Denied` 表示用户拒绝了这次调用。内核把它变成这次调用的错误结果，模型收到用户的理由和“不要重试或绕过”的要求后继续。`ToolOutput::refused` 让它不计入任务失败。
- 数据目录落在工作区内（例如在家目录里启动）时不拒绝启动，而是把它设为受保护目录（`safety/protected.rs`）：文件工具拒绝其中的路径，遍历、ripgrep 和 Git 快照都排除它。工作区是家目录或文件系统根时只警告，不做自动快照。
- Shell 命令按实际方言切分后逐条分类，无法静态判断的写法按“未知”处理。
- 子 Agent 权限和预算不大于父任务剩余额度；并行审批排队，一次只问一个。
- 项目 `.cove.json` 未信任时只应用安全字段；能执行代码、增加花费或改变凭据去向的字段（MCP、系统提示、校验命令、provider、技能市场来源等）需要 `/config trust`。
- Skills 内容、工具输出、网页和记忆是外部输入，不能改变权限规则。
- 浏览器网络访问、URL/重定向和本地服务验证保留明确安全边界。
- 日志与诊断轨迹不记录 API key、认证头或消息正文。

## 9. 验证策略

- Mock Provider 驱动完整“用户任务 → 工具调用 → 工具结果 → 结束”循环。
- SSE 任意分片、UTF-8 分片、错误状态、参数缺失和断流，不误执行工具。
- 无交互缺少审批时快速失败，交互模式能批准、拒绝和取消；拒绝的调用把理由交回模型，任务继续，不计为失败。
- 流式 Markdown 渲染在任意分片下输出一致，样式跨分片不丢失，表格按显示宽度对齐。
- Shell 超时/取消后无所属孤儿进程，stdout/stderr 编码互不破坏。
- 文件修改后的用户漂移不能被 `/undo` 覆盖；不触碰无关文件。
- 压缩、日志重放与恢复不丢需求、工具配对和未知执行状态。
- 所有扩展共用权限、取消和限额；子 Agent 没有更高权限。
- 浏览器断言失败为失败，缺浏览器或缺实操条件为未验证。
- 测试通过证据包含命令、退出码、输出与关联改动；代码再次变化后不能沿用旧结论。

质量门禁：`cargo fmt --check`、`cargo clippy --all-targets --locked -- -D warnings`、`cargo test --locked` 和发布构建。测试使用隔离的临时数据目录和本地模拟服务，不需要真实 API key。

## 10. 当前状态与限制

- 已在 Windows x86_64 GNU / Rust 1.99.1 上验证模拟协议、真实临时文件和子进程操作；未使用真实供应商付费 API，也未完成各模型的兼容认证。macOS、Linux 已配置 CI，在实际运行通过前不宣称验证。
- 界面是滚动输出加常驻输入行，不是全屏 TUI；用户可见文本为简体中文，发给模型的提示和工具结果保持英文。交互外观已在 Windows 伪终端里按字符核对，其他终端的符号显示仍需实机验收。
- 不支持 MCP 的采样、elicitation 和服务端后台任务；`bedrock` 只支持 Bedrock API key，不支持 SigV4。
- 写入模式的子 Agent 和后台 Agent 使用与主任务相同的权限判定，但不经过主任务的计划模式工具和提交前验证包装。
- 后台调用（记忆提取、技能复盘、自审）按主模型单价估算费用。
