# 开源 Agent 任务循环"完成判定"调研与 cove 借鉴清单

日期：2026-09-25。调研对象与源码版本：gemini-cli `bedef96`、Hermes Agent（NousResearch）`fdec926`、Codex CLI `4b1c0c30`、OpenCode `16c56fe`、goose `9adae14`。每条结论都对应读过的源码位置，未核实项已标注。

## 一、共同点：没有人用"完成工具"

五个项目判定"任务做完"的基准完全一致：**模型这一轮回复里没有工具调用，就算结束**。没有任何一个要求模型调用 `task_complete` 之类的工具（Hermes 只在 kanban 工作者模式下强制收尾工具）。差别全在"模型说停之后，还要过几道门"以及"到上限时怎么收场"。

cove 的基准判定与它们相同，已经有的门是：输出被截断自动续写（五者中唯一）、可选的验证命令门禁（按项目推断 `go build` 等，改过文件才跑）。

## 三、值得 cove 借鉴的点（按对 DeepSeek 场景的价值排序）

1. **"宣告下一步却停下"检测（Hermes）。** 弱模型最常见的失败形态：回复结尾写"接下来我将修改 X"却不发工具调用。Hermes 在 `finish_text_response` 里识别这种结尾并注入一次"Continue now"，与"退化结尾"（本轮用过工具，最后只丢一个片段）、"空回复/只有思考块"共用 ≤2 次的配额。cove 完全没有这层，成本极低，收益直接对应"任务完成度不如 Claude Code"的体感。

2. **到上限或用户选停止时，让模型做一次无工具的收尾总结（Hermes、OpenCode）。** cove 现在中断后只有一行错误。改为再调一次模型（禁用工具）输出"已完成 / 未完成 / 建议下一步"，用户拿到的是状态报告而不是断头。`-p` 模式同样受益。

3. **完成前的目标自检一次（goose）。** 模型说停、且本轮改过文件时，注入一次"结束前检查用户的要求是否已全部满足，未满足就继续，满足就给最终答复"。goose 用 `goal_check_pending` 保证每轮只问一次。对 cove 建议只对快模型/中档模型启用（配置 `done_check: auto|on|off`），与现有验证门禁互补：门禁查的是"能不能编译"，自检查的是"有没有做完"。

4. **验证门禁跳过已验证的情况（Hermes verify-on-stop）。** Hermes 不是无条件跑命令，而是看本轮有没有"验证通过"的证据。cove 若模型本轮已经成功跑过 `go build ./...`，门禁再跑一次是浪费。改为：本轮工具结果中已有同命令且退出码 0 → 跳过。

5. **循环检测的第二次处理（gemini-cli）。** 第一次注入反馈续跑 cove 已有；第二次 gemini 停下并让用户选"本会话禁用循环检测并重发"或"保持停止"。cove 累计 5 次才硬停，中间用户没有介入点。建议第 2 次命中即询问，选项含"禁用并继续"。

6. **相同结果去重为存根（Hermes）。** 第 2 次出现完全相同的大段工具结果（≥512 字符）时，上下文里换成"与第 N 条结果相同"的引用。cove 的遮蔽器只按时间裁旧输出，没有按内容去重；对反复 `cat` 同一文件的弱模型很省 token。

7. **中断标记写入历史（Codex）。** Ctrl+C 或上限停止时，在历史里写一条系统说明："本轮被用户中断，命令可能已部分执行，后台进程可能仍在运行"。cove 的 `/continue` 续跑时模型并不知道上一轮为何停，容易重复已做的操作。

8. **预算 80% 提醒（Hermes）。** 迭代窗口或时间窗口用到 80% 时，往最新工具结果上追加一次"剩余约 N 次，请优先收敛；不要仅因此停止"。让模型主动收尾，减少走到询问的次数。

9. **权限拒绝文案（goose）。** cove 现在回给模型的是 `Error: permission denied for bash: …`。goose 的文案明确要求"不要再次调用同一工具，向用户解释情况后停止"，对弱模型反复重试被拒命令的情况有效。

10. **子代理结果结构化（Hermes）。** 在现有 `CapReached` 基础上补 `exit_reason ∈ {completed, max_iterations, interrupted, error}` 与 `truncated`，`execute_plan` 汇总时按原因分类展示。

11. **LLM 循环判定（gemini-cli，可选）。** 30 轮后每 5–15 轮用小模型看最近 20 条历史是否在原地打转，置信度 ≥0.9 才算。成本不低，放在最后；cove 的 L1/L2 已覆盖大部分机械循环。

## 四、不建议照搬的

- **next-speaker 检查（gemini-cli）**：默认关闭，每次结束多一次模型调用，且规则里"回复以问句结尾判 user"对中文表达不稳。第 3 条的"目标自检一次"是更便宜的替代。
- **压缩后禁止续做旧任务（Hermes）**：与 cove"同一轮内压缩后自然继续"的模型冲突，cove 的做法对长任务更友好。
- **取消轮次上限（Codex、gemini）**：cove 用户明确要的是"到点询问"，已经实现，比不限更可控。
